# team leadership

## When to use
Use for related GitHub issues and features; this file is scoped guidance, not a granted external permission.

## Procedure
Read docs/researches-and-tasks/04_GOALS_ROADMAP_AND_LEADERSHIP.md and 05_EXECUTION_TASK_CATALOG.md. Set one measurable outcome weekly, at most two in-progress engineering issues, an owner, an estimate in focused hours and acceptance with exact evidence. Organize roles as responsibilities not payroll; check collaborator consent and least privilege. Every week review actual vs estimated hours, blockers, support risk, user insight, commit/tests and next highest-priority issue. Follow source-of-truth GitHub issues. Account creation must honor vendor terms, MFA, genuine identity and sandbox separation; never instruct quota-evasion or secret sharing.

## Output checklist
- Linked issue, role, required decision and user behavior.
- Source URLs/paths inspected; separate verified behavior from proposal.
- Risks/negative tests; exact results and commit SHA.
- Acceptance/status and next step; do not invent success or approval.
