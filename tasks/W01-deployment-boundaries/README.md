Stacked on the consolidated Week 1 candidate #58. The older content/catalog and course routes now fail closed outside explicitly approved hosted staging, require the dedicated project, reject public registration/live payment mode and validate public vs privileged credentials (legacy JWT role/ref is only config sanity; provider verifies). Local routes remain unchanged. The public taxonomy preview is unavailable until the private staging gates are enabled.
GET /api/internal/health is off unless STUDENT_CREATORS_HEALTH_ENABLED=true and a separate high-entropy STUDENT_CREATORS_HEALTH_TOKEN is privately configured; it returns a generic 404 otherwise. It checks actual Auth settings (signup disabled), zero-row public taxonomy REST query, service-only negative session RPC, public denial of that RPC and exact private bucket metadata. No mutations, provider sends, charges, student records or raw error bodies. A 200 proves only these six foundation probes, not integration/release readiness. A 503 means degradation. No provider health claim without actual authorized execution; tests use synthetic responses.
References: Supabase Auth/Storage APIs and Next.js MIT repository, original implementation no new dependencies. No production release or config modification.
