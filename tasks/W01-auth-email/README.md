# Week 1 Supabase Auth Send Email hook and Resend
The Next route /api/webhooks/auth-email authenticates Supabase Standard Webhooks HMAC before accepting only one approved pilot email for signup/invite/recovery. Plain text OTP; fixed app origin, no token in URLs or stored payloads. The durable ledger stores only keyed HMAC digests (separate stable server pepper), lease and provider ID; identical token deliveries share stable Resend idempotency key, bounded retries and aggregate cap. Provider response means API accepted, not inbox delivery. No email sent by tests.
Uses founder alias resend_api, canonical RESEND_API_KEY and explicit verified RESEND_FROM_EMAIL; requires SUPABASE_AUTH_EMAIL_HOOK_SECRET from Auth Hooks, STUDENT_CREATORS_AUTH_EMAIL_IDEMPOTENCY_SECRET (32+ random URL-safe characters, separate from the hook secret), STUDENT_CREATORS_AUTH_ORIGIN, STUDENT_CREATORS_AUTH_EMAIL_ENABLED, one pilot email, dedicated staging gates. Configure the Supabase Auth hook only after independent review and exact-head CI. The native Auth verify/recovery API and confirmation page are a separate workstream. Recovery enumeration/rate control is managed at Auth API plus application route, not inferred from this hook.
Official Supabase Auth email hook and Resend API docs, upstream Resend MIT and standard-webhooks Apache-2.0 reviewed as references; original implementation, no copied code/dependencies. No live provider configuration, enrollment or send.
