# Week 1 durable Mux delivery
POST /api/webhooks/mux uses the existing raw-byte signature validator and existing durable inbox, adding normalized immutable event type/resource ID atomically. HTTP 200 acknowledges receipt only. A later worker must fetch authoritative current asset/upload state from Mux, validate ownership/association and transition monotonically. Never infer clean scan or approved publication from webhook receipt. The provider upload ID is not necessarily an asset ID. Source review: tasks/W04-media/SOURCE_REVIEW.md (Apache-2.0 upstream SDK, no copied code or new packages).
The endpoint is off by default. Only dedicated staging, public enrollment and live payment disabled, explicitly enabled with STUDENT_CREATORS_MUX_WEBHOOK_ENABLED=true and a distinct MUX_WEBHOOK_SIGNING_SECRET, never a playback signing key. Apply migration only after review. No real webhook/provider flow verified by synthetic tests. No raw payload, email, playback URL, or credentials are stored or returned.
