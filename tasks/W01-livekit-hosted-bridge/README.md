An additional disposable CI acceptance uses upstream LiveKit server v1.13.11 (release archive SHA256 pinned) and livekit-client v2.25.0 (Apache-2.0; ephemeral CI only, no product dependency). It exercises the existing token issuer and Twirp room service against an actual loopback server and two Chromium WebRTC peers with synthetic canvas frames, invalid/expired tokens, participant publish denial, explicit reconnect and room deletion. No cloud credentials, real people or charges. Production TLS endpoint validation is not relaxed; only the injected test fetch maps the fixed fixture origin to loopback. Server auto_create=false is a local test setting, not a claim about LiveKit Cloud configuration or immediate revocation of cached cloud tokens. Real hosted cloud room and app entitlement/browser acceptance remain separate.
