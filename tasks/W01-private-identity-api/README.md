# Week 1 private identity evidence
Depends on PR #50 current-session guard and PR #43 staged private buckets. POST raw JPEG/PNG/PDF to /api/identity/evidence/:requestId using current bearer. Owner and pending manual verification request are checked in the database; one immutable file per request, 4 MiB server limit below the 5 MiB bucket limit. Retry only the identical bytes; digest mismatch is a conflict. Preliminary file signature is not a malware scan. Storage remains private, no public or signed URL issued. GET reauthenticates active admin, records audit, verifies digest, and serves attachment with no-store. No moderator-wide permission or self-review. No identity approval occurs.
Quarantined objects are not served. The scanner worker uses a bounded 90-second SQL lease, at most five attempts with backoff, exact-byte digest checks and a local ClamAV Unix socket INSTREAM protocol. Run node scripts/scan-private-identity.mjs only from an approved scanner host with CLAMD_SOCKET and STUDENT_CREATORS_IDENTITY_SCANNER_ENABLED=true. No remote plaintext scan endpoint. No real ClamAV engine or actual Storage API acceptance has been proven; no real ID documents should be collected. ClamAV GPL-2.0 repository was reviewed only as protocol reference; no code copied or linked. An uncertain upload can be reconciled by repeating identical bytes; abandoned reservations and retention need separate reviewed cleanup. No destructive deletion implemented.
Activation requires dedicated staging, identity privacy approval and explicit upload flag. Upstream official reference: https://supabase.com/docs/guides/storage/security/access-control and https://supabase.com/docs/guides/storage/uploads/standard-uploads (original implementation, no copied SDK or new dependencies). CI models database contract; real provider API tests remain separate.
