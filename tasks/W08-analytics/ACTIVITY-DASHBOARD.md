# Student and creator activity dashboard / future ML contract

Current endpoint: POST /api/social/myActivityDashboard, existing bearer auth, JSON {"days":7} or {"days":28}. No other user IDs accepted. Returns Lagos calendar date buckets, totals and current follow/publish counts. This release reports retained likes, saves, follows, visible authored comments/posts, provider-recorded distinct class joins and own published items; these are not historical impressions, watch time, completion, grades or proof of mastery. The current window includes today and is not an equal-duration comparison with an earlier completed window. No money or private message bodies returned. Creator money remains on the existing myCreatorFinance and myPayouts endpoints.

Future instrumentation: server-authorized playback sessions, validated heartbeats, bounded credited playback duration, distinct viewer aggregation, progress/resume position, completion based on explicitly defined coverage, class attendance duration and assessment attempts. Never trust client events as payment or assessment evidence. Keep event IDs idempotent, session bound, time bounded; separate raw telemetry from owner-visible aggregates. Respect access revocation, consent/retention and deletion requirements. Establish event schema/version and data quality first.

Future ML (not a claim of implemented ML): candidate retrieval from authorized school/course/topic catalog, content embeddings and ranking over safe candidates, then baseline evaluation against existing campus/follow/recency order. Evaluate relevance, coverage, latency, cold start, bias and leakage. Reapply eligibility and access checks after ranking. Separate optional captions/transcription, content moderation assistance and learning recommendations. No automatic identity approval, payout decisions or academic mastery claims. Use pseudonymous IDs and approved data only; no private messages, student ID files, bank evidence or secrets in training inputs. Existing founder model artifacts require model cards, input/output schemas, dependencies, licensing, resource requirements and held-out evaluation before integration. No assumptions about model availability or GPU budget.

Frontend handoff: consume existing activity response without fake counts; show not collected states for watch time/mastery until the instrumented pipeline is verified. Retain the existing independent frontend assignment.

## Playback progress contract
Live playback responses may include watchSession {id,nextSequence,durationMs,resumePositionMs,expiresAt}. Mux's checked asset duration is used, not a client duration. POST /api/social/recordWatchProgress with {watchSessionId,sequence,positionMs,playing,continuous}; report at roughly 15-second intervals while playing, send continuous=false after seeks, buffering, backgrounding or pauses. First report sets a baseline; duplicate/early reports return accepted=false; use nextSequence from the server. Expired sessions require a fresh signed playback grant; only one active session per viewer, so concurrent devices replace one another. Failed telemetry does not deny playback. Dashboard watch object contains bounded estimatedWatchMs, daily summaries, videosWithWatchActivity, authorized resume positions and anonymous aggregate creator audience (distinct reporting viewers, not verified total views). Never convert seek position or reported watch time into learning mastery, verified views, paid rewards or grades. No raw heartbeat history, private message content or payment metadata is collected. Further completion coverage, retention periods, privacy-request integration and real player wiring require acceptance; no model training is enabled.

## Coverage, comparison and privacy
New weeklyComparison compares two complete seven-day windows excluding today in Lagos time; null changePercent means no nonzero prior baseline. Retained records may change when likes/bookmarks are removed. watch.coverage reports estimated union of bounded credited positions, asset-specific and deduplicated; seeking never counts as coverage. Threshold 90% is an engineering heuristic, not evidence of learning mastery. Coverage starts with this migration; existing daily watch totals cannot reconstruct historic unique intervals. POST /api/social/getWatchPreference {} and /api/social/setWatchPreference {"enabled":false} allow a current authenticated student to stop optional video analytics; playback continues, existing history is retained, and no automatic deletion or retention policy is activated. The existing privacy review flow remains applicable to erasure/export; legal retention and reviewed fulfilment are separate.
