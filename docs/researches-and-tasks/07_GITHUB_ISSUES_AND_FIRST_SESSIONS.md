## Project leadership controls
- Primary source: GitHub Issues; board in same GitHub account if user configures it.
- WIP limit: 2 technical issues; blocked items stay visible.
- Required issue fields: role owner, priority, estimated/actual focused hours, target date, dependencies, acceptance and real evidence.
- Weekly goals: one user outcome, one testable increment, one quality/reliability proof.
- Label milestones as proposed, test-verified, staged, public only when those states are true.
- Private student names, emails, identities, PSP secrets and informal relationships never belong in public tickets.
